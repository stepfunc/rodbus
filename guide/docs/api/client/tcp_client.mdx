The `ClientChannel` class represents a communication channel for making requests to server devices. The channel presents the same interface regardless of underlying transport. Create a TCP client channel using the `create_tcp` method.

:::note
In Rust, you can use `spawn_tcp_client_task` to create a channel and spawn its task in the current runtime.
Otherwise, `create_tcp_client_task_with_options` returns the `Channel` and a `ClientTask`; spawn `task.run()` when ready.
:::

## Enabling

The channel is created disabled: it doesn't connect until you call `enable`, and requests made while it has no connection fail
with a `NoConnection` error. Once enabled, it keeps a connection open, reconnecting when it fails. Call `disable` to close the
connection and stop communicating.

## Endpoint

The remote endpoint is a host and a port, where the host is an IPv4 address, an IPv6 address, or a DNS name that the library
resolves. In Rust, pass a `HostAddr`, created with `HostAddr::ip` or `HostAddr::dns`.

## Retry strategy

The `RetryStrategy` controls how often the client retries. After each failed connection attempt it waits, doubling the
wait from `min_delay` up to `max_delay`; after an established connection closes, it waits `min_delay`.

## Maximum queued requests

The channel sends one request at a time and queues the rest, up to `max_queued_requests`. When the queue is full, a request
made in the bindings fails with the `TOO_MANY_REQUESTS` error, while one made in Rust waits for room.

## ClientStateListener

The `ClientStateListener` interface (`Listener<ClientState>` in Rust) has a single callback that informs your code about the state of
the connection: disabled, connecting, connected, waiting to retry after a failed connection attempt or a disconnection, and shut down.
